# 語意回憶：瀏覽紀錄語意搜尋（Chrome 擴充功能 v0.5）

用一句話找回讀過的網頁：「上週看的 flash-attn Windows 編譯失敗」「vLLM KV cache 不夠的那篇」。
EmbeddingGemma-2 在本機（WebGPU）建索引，網頁內容和向量只存在這台電腦的 IndexedDB。

## 安裝

1. 解壓縮 → `chrome://extensions` → 開「開發人員模式」→「載入未封裝項目」選這個資料夾
2. 打開搜尋頁（`Alt+Shift+F` 或點擴充功能圖示 →「完整搜尋頁」）→ 按「匯入最近 30 天紀錄」
   - 第一次會下載 EmbeddingGemma-2 270M（之後存在 Cache API）
   - 匯入只用「標題＋網址」，馬上能搜；之後正常瀏覽會自動補上全文
3. 已經開著的分頁要重新整理，內容腳本才會生效

## 使用

| 方式 | 操作 |
|---|---|
| 網址列 | 輸入 `ss` + 空白 + 查詢，下拉直接出結果 |
| 搜尋頁 | `Alt+Shift+F`，可篩時間、網站，移除單頁或整個網域 |
| 立即索引 | `Alt+Shift+S`，或 popup「索引此頁」 |

自動索引條件：頁面**可見**累計 20 秒（可調）、文字 ≥ 300 字、不在排除清單、不是無痕、畫面上沒有**顯示中的**密碼／信用卡欄位（隱藏的登入彈窗不算）。有的話右下角顯示 🔒，手動「索引此頁」仍可索引。
同一頁內容沒變不會重算，只更新造訪時間；SPA（GitHub、文件站）換頁會重新計時。

## 分類（自動貼標籤）

預設 9 個分類（AI／機器學習、GPU／CUDA、語音 ASR／TTS、除錯／解法、文件／教學、部署／雲端、投資理財、新聞時事、生活旅遊），
可在搜尋頁「管理分類」改名、改描述、改顏色、刪除，或新增自己的分類。

- **自動分類**：頁面向量 vs 分類「原型」的相似度。原型＝分類名稱＋描述的 embedding（權重 2）＋所有你手動標記成這個分類的頁面。
  所以**你手動修正得越多，自動分類越準**，不用重新訓練。
- **多標籤規則**（`store.js` `pickTags`）：最高分要超過門檻、且明顯高於平均（否則算「未分類」）；
  與最高分差距 0.04 內的分類一起標上，最多 3 個。門檻可在設定調整。
- **手動優先**：手動加的標籤是實線；自動的是虛線。按 × 移除自動標籤後，之後不會再自動加回。
- 搜尋頁上方是分類 chip：點一下篩選；**搜尋框留空＋點分類＝瀏覽這個分類最近的頁面**。
- 結果卡片的「分類分數」會列出這頁和每個分類的實際相似度，用來校準門檻或改描述。
- 網頁右下角圓點的選單也能直接切換這頁的分類。

## 📌 片段：只索引頁面上的某一塊

很多文件頁很長，真正有用的只是一段（例如 AWS 文件裡的某個 `<p>`）。

| 方式 | 操作 |
|---|---|
| 選取模式 | `Alt+Shift+E`、popup「📌 選取區塊索引」或圓點選單 → 滑鼠移到區塊（像 DevTools 一樣顯示 `p 549.5 × 168`）→ `↑` 父層／`↓` 子層 → 點擊 |
| 右鍵 | 在區塊上按右鍵 →「語意回憶：索引這個區塊」（自動往上找到合適的段落） |
| 選取文字 | 反白文字 → 右鍵 →「語意回憶：索引選取的文字」 |

確認面板可以加備註（備註也會被搜尋）。片段是獨立的索引項目，會自動分類；
搜尋結果的連結帶 Chrome text fragment（`#:~:text=`），點開會直接捲到那一段並反白。
搜尋頁「📌 片段」chip 可以只看片段。片段不受排除清單限制（是你主動選的），但無痕視窗一樣不存。

## 區塊索引的三種模式

popup 或搜尋頁設定切換（`blockMode`）：

| 模式 | 行為 |
|---|---|
| 關閉 | 不顯示任何區塊 UI；快捷鍵與右鍵會提示已關閉 |
| 點了才選（預設） | `Alt+Shift+E`／popup／圓點選單／右鍵 → 選取模式 |
| 自動標出可索引區塊 | 載入後在每個可索引區塊右上角出現小圓點：`+` 文字區塊、`🖼` 圖片；點一下索引 → `✓`；再點 `✓` 移除 |

自動標出的規則：段落類元素（p、li、pre、blockquote、td、dd）文字 ≥ 80 字、取最內層容器；
圖片 ≥ 120×120；文字排除 nav／header／footer／aside／form，**圖片只排除 nav／footer／form**（首頁大圖常在 header、輪播圖常帶 aria-hidden）。
lazy-load 圖片換上真正的 src 或載入完成時會重新掃描；選取模式遇到透明連結／漸層蓋在圖片上時，會穿透到下面的圖片。只為畫面附近的區塊畫圓點，頁面變動 1.5 秒後重新掃描。
已索引過的區塊（以內容 hash 比對）重新開頁時直接顯示 `✓`。同一區塊重複索引會更新，不會產生重複。

## 搜尋相似度門檻

搜尋結果上方有「文字相似度 ≥」滑桿，圖片區另有一條（兩個模型的分數尺度不同，所以分開）。
每筆結果顯示它的相似度，滑桿旁顯示本次查詢的相似度範圍，方便找到適合的門檻；低於門檻的筆數會列出，可一鍵顯示全部。
門檻存在設定裡（`searchMinSim`、`imageMinSim`），拖動時直接過濾，不會重新查詢。

## 🖼 圖片（預設不索引）

一般頁面索引**預設不包含圖片**。設定或 popup 可開「自動索引時一併索引圖片」：頁面自動索引完成後，
內文裡 ≥ 200×150 的圖片（每頁最多 8 張，排除 nav／footer／aside／表單、SVG、重複圖）會一起索引，**只用原圖、不捲動不截圖**，
同一張圖不重算，也受排除清單限制。手動索引圖片：右鍵 →「語意回憶：索引這張圖片」、選取模式點圖片（或勾「以圖片索引」把任何區塊當截圖，例如圖表），
或自動標出模式的 `🖼`。

- 取得內容：先抓原始圖檔（完整解析度）；抓不到（canvas、SVG、CSS 背景、權限）就截取畫面上該區塊
- 圖片需要能吃圖的模型，所以**圖片索引固定用 EmbeddingGemma-2 Text-Vision 440M**，存在獨立的 IndexedDB（`semhist-img`）；
  文字索引維持你選的模型。440M 只在第一次索引圖片時下載、載入
- 搜尋時用文字查圖（同一個 440M 把查詢轉向量），圖片結果以縮圖列在文字結果上方，兩邊分數不混排
- 分類同步到兩個索引，圖片也會自動分類；「🖼 圖片」chip 可瀏覽所有圖片
- 截圖只截得到畫面內的部分；比視窗還大的圖片若抓不到原檔會被裁切

## 網頁上的狀態圖示

每個頁面右下角有一個小圓點，顯示這頁在索引流程中的狀態；點它會跳出選單（立即索引、重新索引、從索引移除、在此網站隱藏圖示）。

| 狀態 | 圖示 | 說明 |
|---|---|---|
| WAITING | 藍色進度環（已索引過的頁面中間有淡 ✓） | 頁面可見，累計停留中 |
| PAUSED | 灰色進度環 | 分頁在背景，計時暫停 |
| INDEXING | 旋轉環 | embedding 計算中 |
| INDEXED | 綠色 ✓（3 秒後變淡） | 完成，或內容未變 |
| ERROR | 紅色 ! | 失敗，點擊重試 |
| REMOVED | 灰色 − | 已移除，這次造訪不會自動再索引 |
| INELIGIBLE | 文字太少顯示 ∅；排除清單、密碼頁不顯示 | |
| INIT / DISABLED | 不顯示 | |

狀態機是 `content.js` 裡的純函式 `transition(ctx, event)`，圖示只是它的 view；
設定頁可關閉圖示或指定網域隱藏（隱藏圖示不影響索引）。

## 架構

```
content.js            停留計時、抽 <article>/<main> 文字、SPA 換頁偵測
   ↓ INDEX
background.js         排除清單、無痕過濾、網址列 ss、快捷鍵、匯入 chrome.history
   ↓
offscreen.js          UniversalEmbedder（WebGPU）
  ├ chunk.js          段落切塊 600 字、重疊 100、每頁最多 16 塊
  └ store.js          IndexedDB 持久化 + 記憶體 Float32Array 暴力 cosine
                      混合排序：語意（chunk max-pool）＋ 關鍵字加分 ＋ 近期加分
```

- 向量用 Matryoshka 截到 256 維再正規化，2 萬段約 20 MB
- 查詢與文件用 EmbeddingGemma 的非對稱 prompt（`shared.js` 的 `PROMPT`）
- 關鍵字加分是為了技術搜尋：錯誤碼、套件名（`C2975`、`flash-attn`）語意模型容易抓不準
- 換模型會清空索引（不同模型的向量空間不相容）

## 調整

| 想改 | 位置 |
|---|---|
| 向量維度 | `shared.js` `DIM`（改了要清空索引） |
| prompt 格式 | `shared.js` `PROMPT` |
| 排序權重 | `store.js` `search()`：關鍵字 0.08/0.05、上限 0.24；近期 0.03 |
| 切塊大小 | `chunk.js` `chunkText()` 預設參數 |
| 預設排除網站 | `shared.js` `DEFAULT_DENYLIST`（搜尋頁設定也能改） |

## 輸入長度限制（v0.4.1 修正）

LiteRT 模型的輸入有固定長度 signature（建立時設 `maxInputLength: 512` tokens），超過就回
`INVALID_ARGUMENT: Failed to compute text embedding.`。中文約 1 字 1 token，所以切塊改用**估計 token 數**
（`chunk.js` `estimateTokens`，中文 ×1.2、emoji 等 ×2、ASCII ÷3，刻意高估）：每塊 ≤ 360 tokens，標題截 60 字、查詢截 200 字。
萬一估計仍偏低，`offscreen.js` 的 `vec()` 會把輸入縮短 40% 重試，最多 4 次。中文頁每頁上限 32 塊。

## 驗證狀態

- `store.js` / `chunk.js`：用 fake-indexeddb + 模擬 embedder 測過新增、搜尋（中英、錯誤碼）、
  重新索引、重載後持久化、刪除、網域與時間篩選
- `content.js`：jsdom 測過停留後自動索引、網址正規化、`INDEX_NOW`
- 排除清單比對已測
- 分類：多標籤規則、預設分類種子、手動移除不再自動加回、手動標記成為原型範例並影響相似頁面、
  新增／刪除分類後重新分類、v1 → v2 資料庫遷移，皆已用模擬 embedder 測過
- 片段：選取模式（hover、↑↓、點擊不觸發網頁連結、Esc）、右鍵找最近段落、選取文字、text fragment 編碼（含中文與 `-`）、
  圓點選單切換分類，皆已用 jsdom 測過
- 區塊模式與圖片：候選區塊規則、已索引 ✓ 還原、+ → ✓ → + 切換、圖片送出時隱藏自身 UI、picker 圖片模式、三種模式切換，
  皆已用 jsdom 測過；圖片索引的獨立資料庫與分類同步已測
- **圖片像素處理（原圖抓取、截圖裁切、embedImage）完全依賴真實瀏覽器，沒有辦法在這裡測**
- **尚未在真實 Chrome + 真實模型上跑過**；模型 API 依 `@mediapipe/tasks-retrieval` 1.2.3 型別定義撰寫

## 已知限制

- Chrome 內建 PDF 檢視器裡的 PDF 不會被索引（內容腳本進不去）
- 需要登入才看得到的頁面一樣會被索引（例如公司內部 wiki）——不想要的話加進排除清單
- 暴力搜尋在 10 萬段以上會開始變慢，到時候再換 HNSW
